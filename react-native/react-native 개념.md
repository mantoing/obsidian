### react-native란?

##### **React 는 과연 웹에서만 사용가능한것일까?**

- React.js 는 인터페이스 구축을 위한 Javascript 라이브러리이다.
  보통 웹개발에 사용된다. 애초에 웹 환경을 위해 생성된것!
  
  하지만 내부를 뜯어보면 결국 **react-dom** 라이브러리가 웹지원을 돕는다.
  react-dom 없이 React 라이브러리 자체는 **플랫폼 애그노스틱(platform-agnostic)** 이기 떄문이다.
  > 플랫폼 애그노스틱 : **어떠한 운영 체제나 프로세서의 조합인지에 대한 아무런 지식이 없더라도 상관없이 기능을 수행할 수 있는 소프트웨어 기술**
  
  
  즉! React와 react-dom을 함께 사용해 웹 앱을 구축할 수 있지만 **React 라이브러리 자체는 플랫폼에 구애 받지 않는다는 뜻이다.**
  
  React는 상태(State)를 관리하고 가상의 컴포넌트 트리를 구축하는 툴일 뿐이다.
  
  그렇다면 React Natice는 쉽게 말해 앱환경에서 사용할수 없는 react-dom의 대안이다!!
  플랫폼 대상이 웹 브라우저가 아니라 iOS 와 Android 라는 말이다.
  
  따라서 React Native를 알기 위해선 결국 React 를 알아야 한다는 뜻이다

### React Native의 원리?

``` jsx

const App = props => {
	return (
		<view>
			<Text>Hellod there!</Text>
		<view>	
	);
};
```

보통의 react jsx 과 비슷해 보이지만 웹 어플리케이션을 만들던 사람들에게는 생소한
`<view>, <Text>` 라는 컴포넌트가 보일것이다. 이는 React Native가 컴파일 할것인데. 
이때 보통의 javascript 논리가 아닌 `view` 라는 jsx코드만 컴파일이 된다.

즉 사용한 JSX 요소는 각 플랫폼의 네이티브 요소로 컴파일된다.

![[스크린샷 2024-07-16 오후 1.22.43.png]]


각 요소를 위한 React Native의 컴포넌트이다.

![[스크린샷 2024-07-16 오후 1.23.57.png]]

쉽게 말해서 각 네이티브 컴포넌트들을 각각의 약속들에 의해서 컴파일 한다는 의미이다. 
즉, React Native 는 재사용 가능한 컴포넌트를 매핑하고 컴파일 한다.

#### 그렇다면 논리는?

UI 요소와 다르게 논리는 컴파일 되지 않는다. 
React Native의 컴포넌트인 UI 요소는 컴파일이 된다.
반면, JavaScript에서 작성한 논리는 컴파일되지 않고 구축한 네이티브 앱 안에서 React Native가 호스트한 대로 JavaScript 스레드에서 실행된다.

즉! React Native는 간단한 JavaScript 프로세스를 구축하고 있는 네이티브 앱의 일부로 만들어 자동으로 이 프로세스를 관리해 네이티브 플랫폼과 상호작용할 수 있도록 한다.

따라서, JavaScript 코드는 구축하고 있는 네이티브 앱 안에서 JavasCript 그대로 실행하면서 네이티브 앱의 React Native를 통해 언어의 장벽을 넘어 Android 나 iOS 플랫폼과 상호작용한다.

### react Native 프로젝트 생성하기

 공식 홈페이지를 들어가게 되서 환경세팅 부분을 가게되면 
 **Expo CLI** 와 **React Native CLI** 가있다.
 두개의 차이점은 무엇일까 ?

두 가지 툴 모두 React Native 프로젝트를 생성하고 테스팅 기기 및 시뮬레이터에 React Native 앱을 실행할 뿐만 아니라 React Native 앱을 구축하는 데 사용되어 앱스토어에 앱을 배포할 수 있게 한다.

#### 차이점

1. Expo
	- Third-party-service : 완전한 무료 서비스, 추가적인 유료서비스를 제공하지만 React Native 앱을 구축하고 출시하기 위해서는 비용을 지불할 필요가 없다.
	- 정리된 앱 개발 : 프로젝트 생성이 수월하고 코드 작성이 비교적 쉬우며 네이티브 기기의 카메등의 기능을 활용하는것이 전반적으로 쉬워진다는 의미이다.
	- 제공하는 툴 : 제공하는 툴로 네이티브 앱을 작성하면 React Native CLI만 사용하는 것보다 훨씬 편리하고 과정이 수월해진다.
	- 언제든 Switch 가능함 : 만약 필요하다면 원할때 언제든 expo 방식을 종료하고 React Native CLI로 변환할수있다.
	
2. React Native CLI
	- React Native 팀과 커뮤니티가 만들었다. : 초기에 React Native 팀에서 생성했다.
	- Bare-bone development : 초기 환경 설정과 셋업을 직접 하나하나 모두 다해야한다. (필요한 세팅과 설정만 할수 있지만 문제는 상당히 복잡하다.)
	- 특정 기기연결의 번거로움 : 카메라나 마이크등 기타 디바이스를 통제할때 expo보다 조금더 번거롭고 복잡하다.
	그렇다면 왜 react Native CLI를 사용하는걸까 ?
	- 네이티브 소스들과의 손쉬운 변환성 : 자바, 코틀린, 스위프트 등 원래 기존의 어려운 언어로 작성된 코드들과의 호환성이 좋기 떄문에 기존의 앱 어플리케이션의 변환이 손쉽다.
	그런데 엄밀히 말하자면 이러만 과정을 더 손쉽게 하기 위해서 react Native를 사용하는 것이기 때문에 장점이라고 볼 수 없다. 

따라서 우리는 거의 대부분의 새로운 React Native앱을 구축할때 기존의 React Native앱을 사용하는 것 보다 expo를 대부분 사용하게 될 것 이다.
